# ASTRA P90 — 로컬 한국어 윤문 보호 토큰 보강 (2026-11-14 KST)

## 문제와 선택
- 기존 `stableTokens`는 URL, 숫자, ASCII 따옴표만 보호하며, 부호 `-100`↔`+100` 또는 '없습니다'↔'있습니다' 등의 변화가 숫자·인용문 보존 조건을 우회할 수 있었다. 실제 모델은 여전히 차단(`RELEASE_MANIFEST=null`).
- 설계 A: 기존 정규식 유지. 코드·비용은 적으나 금액 부호·부정문 변경 감지 실패 위험을 유지.
- **설계 B 채택:** 기존 규칙을 보존하면서 부호/통화 기호가 있는 수치, 한국어 굽은 따옴표/인용, 부정·거부·취소·제외·금지 표현의 위험 단어 수 변화를 fail closed로 거부. 추가 패키지/클라우드/API/모델 비용 0.
- **한계:** 단순 어휘·기호 불변 검사는 의미보존 또는 고유명사·표 전체 정확성을 증명하지 못한다. 정상 윤문도 보수적으로 거부할 수 있으며, 실GGUF/실사용 20+ 골든 문단은 별도 필수. 실제 모델 활성화·판매 주장 불가.

## 구현·검증
- `desktop/local-model-controller.cjs`: 임시파일·spawn·cancel·SHA/중복요청 방어와 기본 `RELEASE_MANIFEST=null` 유지. `stableTokens`만 보강, 숫자 부호/통화·UTF-8 인용·한국어 부정 토큰 보존.
- `tests/local-model-controller.test.cjs`: 합성 보호 예문 20개(문자 변경 허용 4 / 내용 변경 거부 16) + 핵심 부정 검사 3개. 사용자 문서/실모델/모델가중치/유료 네트워크 불사용.
- 독립 Node22.16.0 합성 초안 검사 20/20 PASS. 원격 정확 SHA 전체 npm/build/Chromium/Windows CI는 반영 후 확인. 앞선 P89 성공 테스트는 P90에 자동 승계 금지.
- 3만·6만·9만 원 SKU 모두 실제 모델의 품질을 같게 제공할 최종 목표는 변하지 않음. 실제 GGUF 파일 SHA/NOTICE/재배포권·고객 PC 성능 및 수용·실한국어 품질이 미검증이므로 `RELEASE HOLD`, 최종 완성률 공식 `UNASSESSED`.
