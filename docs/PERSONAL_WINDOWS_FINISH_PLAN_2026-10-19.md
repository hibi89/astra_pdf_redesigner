# ASTRA PDF Redesigner — Windows 개인용 빠른 완성 계획 (2026-10-19)

## 목표 변경 (사용자 승인)
상용 배포가 아니라 **본인 Windows PC에서 사용 가능한 개인용 프로그램**을 가장 빠르게 완성한다. 기존 코드/문서/데이터를 유지하고 다시 만들지 않는다.

## 1차 완료 범위
1. 현재 Electron 앱을 본인 Windows PC에서 실행한다. 설치판 대신 개발용 `npm run desktop:run`도 허용한다.
2. 합성 테스트 문서에서 제목·본문·테마 편집, 이미지 삽입을 확인한다.
3. 저장 상태 확인 → 앱 종료 → 재실행 → 본문·이미지 복원을 확인한다.
4. Windows PDF 저장 → 생성 PDF 열기 → A4·한글·마지막 문단·이미지·페이지 나눔을 육안 확인한다.
5. `.localdoc.json` 내보내기로 백업한 뒤 별도 테스트 프로필에서 가져오기를 확인한다.
6. 치명적인 데이터 손실, 앱 실행, PDF 출력 결함만 우선 수정한다.

## 범위 제외 / 보류
- 코드 서명·SmartScreen 최적화·자동 업데이트·배포/마케팅·상용 설치/제거 인증
- 다중 사용자·고급 버전 호환성 검증 추가 확대
- STEP4 및 신규 기능 개발
- **STEP3 기존 PDF 업로드/리디자인은 현재 구현되지 않았으며 1차 완료에 포함하지 않는다.** 이 기능이 필요하면 별도 후속 작업으로 명시한다.

## 작업 및 안전 규칙
- 작업 브랜치: `codex/p5-windows-reliability`. PR #7 Draft 유지, 병합 금지. `main` 및 PR #3~#6 변경 금지.
- 사용자 실데이터·설치 앱·브라우저 프로필을 시험에 사용하지 않는다. 별도 합성 문서·격리 프로필만 사용한다.
- 기존 로컬 미추적 `package-lock.json`과 `ershaeinastra-step2-check` 보존.
- 테스트 성공과 미검증을 구분한다. 기존 Windows Server 2025 CI 성공은 본인 Windows 10/11 수동 검증을 대체하지 않는다.
- 기존 PR #7 Windows versionchange 및 CI 검증은 완료 증거로 재사용하고 반복하지 않는다.

## 즉시 실행할 다음 작업
1. Windows 로컬 `git status --short --branch`로 변경/미추적 파일 확인 후 최신 브랜치 문서만 안전하게 반영.
2. `npm run desktop:run` 또는 검증된 시험판을 **격리 테스트 프로필**에서 실행. 실제 설치 앱 변경 금지.
3. 위 1차 완료 항목을 실사용 스모크 테스트하고 PASS/FAIL/미검증 표를 기록.
4. 실패한 필수 기능만 수정, 관련 테스트 실행, 이 브랜치에 커밋·푸시.
5. Windows 사용자 직접 육안 확인이 필요한 경우 그 항목만 명확히 요청.

## 완료 판정
개인 Windows 환경에서 앱 실행, 편집, 이미지, 재실행 복원, PDF 생성/열기, 백업을 확인한 후에만 **개인용 1차 완성**으로 기록한다. 원본 PDF 리디자인은 별도 범위다.

## 시간 추정
현재 기능에 치명적 결함이 없다면 2~4시간 목표, 문제 발생 시 4~8시간 이상 가능. 실제 검증 전 확정 견적 아님.
