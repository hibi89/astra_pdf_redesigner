## Real verification introduced
1. `tests/pdf-integrity-audit.mjs` independently uses PDF.js to open the final saved PDF; verifies A4 dimensions on each page, marker cardinality (exactly once), expected marker sequence, text bounding geometry and raster draw operations.
2. `tests/step3-browser.mjs`: runs both on synthetic two-page multi-column/vector-table/raster source and the actual Chrome/Edge reflowed A4 result, in addition to prior `pdftotext` / `pdfinfo` / `pdfimages` checks.
3. `tests/verify-desktop-pdf.mjs`: applies same independent audit to PDFs generated by the *installed Windows application* for both existing basic fixtures and actual STEP3 import→A4 save.
4. `tests/pdf-integrity-audit.test.cjs` regression tests missing tokens, duplicate tokens, inverted order, valid and overflow text positions, and a real generated two-page PDF. Package test command includes these three added tests.
5. Earlier initial CI SHA `ce4fdcc6217bb75f7a61085ae273fdacf1a4dcdd` failed because two **test case examples were invalid**: single-letter tokens overlapped other words; an expected out-of-page baseline was actually inside the page. Corrected in tested SHA `31b49918`.

## Specific interpretation and limits
- A4 text bounding bounds are based on **PDF.js-reported text geometry** for horizontal text. Non-horizontal text increments `skippedRotation`; tests **fail** if rotated text is encountered rather than silently claiming it passed. This checks probable out-of-page extents, **not** real glyph clipping or OCR.
- Source and reflow must contain all 13 unique exact synthetic markers in expected order; raster operations must exist. **No original pixel, table-grid, vector geometry or same-page-count guarantee.**
- Real customer PDFs, Windows consumer machine/SmartScreen, inaccessible scans, password PDFs, and all SKU template counts **NOT VERIFIED**. M04 here means baseline synthetic accuracy, not commercial launch acceptance.
