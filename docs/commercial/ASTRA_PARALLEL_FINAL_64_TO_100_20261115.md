3. 기능 단위 최소 CI 필요; 승인된 필수 Ubuntu/Chrome/Edge, Windows Electron/NSIS, 정책 검사는 실제 성공 확인 전 완료 표기 금지. CI 큐 대기 때는 증거 분석/독립 단위 진행하되 점수 +0.
4. Codex 작업마다 PR `codex/... → integration/...`로 제안. GPT 작업마다 PR `gpt/... → integration/...`로 제안. PR을 만들었다고 자동 병합/출시가 아니다. 동일 파일 변경 겹침/원장 동기화는 **통합 총괄**만 담당한다. 기존 PR #10/legacy와 main 그대로.
5. 상대방이 아직 push하지 않은 변경·미커밋 작업을 읽거나 의존하지 않는다. 외부 사용자/도구가 Codex 세션을 재개해야 Codex 작업이 진행된다. GPT도 사용자의 다음 `ㄱ` 지시를 받은 해당 응답에서만 실제 작업한다. 백그라운드 동시 실행을 가장하지 않는다.
6. 실패 1회 원인→개선 재시도 1회. 진전 없이 2회 실패 시 Stop & Pivot, 다른 독립 단위. 원본 DB/저장 데이터 복구 절차 없이 migration/merge 금지.
7. 각 단계 보고: `task ID | 정확 branch/SHA | 변경 경로 | 실제 테스트 PASS/FAIL/SKIP | 신규 증거/미검증 | blocker | 점수 변동(근거 없으면 +0) | 다음 READY`. 마지막에는 10항 HANDOFF 및 STATUS 일치.
8. **A11/A12/최종 출시 게이트는 오너 승인 필수.** 외부 원본·모델·OCR·서명 키·판매자 계정/결제/크몽 등록/유료 리소스/프로덕션 보안 변경은 한 번에 구체 승인 요청. 검증되지 않은 미완료를 단순 축소로 덮지 않는다.

## 6. 최종 100% 수용 게이트

- 기술: 사용자 12영역 요구 ID→실제 코드/실행 화면→정확 SHA 테스트 증거, PASS/FAIL/SKIP 분리, 100점 모두 독립 검증. GitHub 기능 HEAD와 통합 HEAD·릴리스 후보 SHA의 일치 확인.
- 품질: 원본 PDF 5~10건 실제 수동 허가 대조, 한글/표/다단/이미지/스캔, 미지원 경고, 30 디자인, 실제 Windows 10/11 설치·인쇄·데이터 복원·성능.
- 보안·라이선스: 모든 외부 자산의 재배포권, NOTICE/라이선스, 안전한 IPC·사인·사용자 정보 노출 방지, 서명·SmartScreen/고객 빌드 권한.
- 운영: 구매자 지원/환불/철회, 가격/상품 정보·크몽 업로드는 별도 이후 승인이 있을 때만 진행. 본 개발로 크몽 등록 완료를 표시하지 않는다.
- 최종 판정: 실증되지 않은 영역은 **UNASSESSED/NOT VERIFIED/RELEASE HOLD**. 공식 100%·판매 GO는 모든 증거 및 사용자 명시 승인 후에만.

## 7. 중간 목표와 시작 명령

- 우선 `C001=P124`, `G001=P119` **동시에 독립 실행**.
- C001 완료 뒤 C003/C005/C006/C007 등 선행 독립 작업으로 전환. P119 미해결 시 OCR 연동을 재시도만 하지 말고 A08/A09/A06/A10의 독립 과제로 피벗.
- 목표 65/70/85/95/100은 단계별 검증 게이트, 수행시간/자동 점수 상승 약속 아님.
- 새 채팅 또는 모바일에서 `ㄱ`은 **현재 담당 브랜치의 다음 READY 작업을 실제 진행**하는 명령이며, 이미 PASS한 단위 반복 금지.
