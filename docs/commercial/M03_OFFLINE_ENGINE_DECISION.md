# ASTRA M03 — 오프라인 규칙 검사·실제 로컬 LLM의 분리 의사결정
확인일: 2026-10-25 KST | 상태: **규칙 제안 코드 구현 / LLM 미연동·미실행·미검증**.

## 구현 단계와 표시 원칙
- M03-A: React 문단마다 **사용자가 먼저 눌러야 하는** '규칙 제안 검토' → 원문/후보 간 차이 → 거부 / 승인 / 직전 적용 되돌리기. 추가 모델·외부 API·토큰·네트워크 호출 없음. `src/humanize/rules.ts`, `RuleReview.tsx`; CI SHA 별도 기록.
- 규칙 예시는 제한된 한글 사이 중복 공백 정리와 `확인하였습니다 → 확인했습니다`처럼 사전 정의된 문체 축약뿐. 인용문 내부, 표/들여쓰기, 과도하게 긴 입력은 보호. URL·수치·영문 대문자 토큰과 인용문 스냅샷이 달라지면 제안 차단. **'자연스러운 AI 윤문'과 다름.**
- 현재 되돌리기는 **열려 있는 블록의 마지막 승인 1회**에만 제공하며 앱 재실행/추가 수동 편집 뒤 기록이 남는 영구 이력 기능이 아님. 원문 PDF 바이트 보존과 별개.
- M03-B: 실제 작은 로컬 추론 모델, 한국어 의미보존, CPU/용량/라이선스 테스트 통과 전까지 **NOT IMPLEMENTED / NOT VERIFIED / 출시 NO-GO**.

## 두 설계안 (성능·비용·유지보수)
| 안 | 실행 경계 | 장점 | 비용/위험 | 권고 |
|---|---|---|---|---|
| A. JS/TS deterministic (구현됨) | Electron renderer, 현재 React state/IDB 사용 | 0 모델 설치, 0 API 비용, 빠른 규칙 검사, 기존 출력/저장 호환 | 자유로운 한국어 윤문 거의 불가; 이름·서법 의미보존 완전 보장 불가 | **즉시 사용 가능한 초안 보조 기능**, AI라고 광고 금지 |
| B. 별도 `llama.cpp` CLI + 로컬 GGUF | sandboxed renderer → 좁은 preload IPC → Electron main이 화이트리스트된 CLI를 `spawn` (shell:false, stdin) → stdout 후보 텍스트만 전달 | 고객 텍스트 외부 송신 없이 오프라인, 서버 포트/외부 fetch 불필요, 모델 교체 가능 | 모델 추가 배포·수백 MB, CPU 속도/품질 미측정, 프로세스 관리·취소·라이선스 필수 | **실제 AI 윤문 구현 시 우선 검토할 안** |
| C. `llama-server` localhost | Electron main에서 `127.0.0.1` 서버 실행/고정 포트/서버 API 프록시 | 연속 요청 빠를 가능성, 표준 JSON 응답 | 포트 충돌·로컬 서버 노출·CORS·기존 `http*` 차단 정책과 충돌, IPC와 프로세스 수명 관리 증가 | MVP 보류 |

## 실 모델 후보 / 외부 검증 (실행 증거 아님)
- 1차 소형 후보: 공식 [Qwen3-0.6B GGUF](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF). 해당 모델 저장소에 Apache-2.0 표기, 모델카드 및 GGUF 파일 제공. 공식 [Qwen3](https://github.com/QwenLM/Qwen3)도 오픈 모델 Apache-2.0이라고 고지. 재배포 시 각 모델/양자화 파일 라이선스와 공지·저작권 고지 직접 확인 필요.
- 런타임 후보: [ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp), CPU/GPU 로컬 추론 지원, [llama-server 문서](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)는 loopback 서버도 안내함. 이번 MVP는 서버 경로보다 CLI IPC 설계를 우선.
- **아직 다운로드도 추론도 하지 않았음.** 특정 CPU에서의 0.6B 한국어 품질/속도/메모리, 설치 서명, 모델 상업 재배포 및 OSS 고지 완결 여부, GGUF 바이너리 해시 **미검증**. 사용자의 비용·데이터 전송 승인 전 대용량 모델을 CI/로컬에 무단 다운로드하지 않는다.

## 실제 로컬 모델 수용 전 필수 게이트
1. 파일 출처/버전/SHA256/실측 용량, 모델+추론기 라이선스·저작권·NOTICE 확정. GitHub에는 가중치 금지.
2. 오프라인 모드 강제: 외부 도메인 패킷 0, 모델 미설치 때 규칙 제안 정상 동작, 최초 다운로드·업데이트는 별도 명시적 승인.
3. 사용자가 블록을 선택한 경우에만 모델 실행. 자동 적용 불가, 출력 전후 글자·문장 diff와 수동 승인·거부·되돌리기. 모델 오류/타임아웃/취소/중복 실행 시 원문 유지.
4. 최소 20개 이상 한국어 골든 문단: 금액, 날짜, 숫자, 통화, 부정문, 인용, 고유명사/법률 표현/표 인접 텍스트의 내용 변조·환각 검사. 정규식 검사는 완전한 의미 검증이 아니므로 사람이 검수.
5. Windows x64 CPU-only 실기기/CI 분리 벤치: 초안 토큰/초, 평균·95퍼센타일 응답시간, 피크 RAM, CPU 점유, 8/16GB에서 설치·재실행·손상 파일 거부, 장문 회귀. 실제 사용 결과만 합격.
6. 기존 Electron `webRequest.onBeforeRequest` HTTP 차단 유지. 임의 명령 실행·쉘 문자열 조합 금지. 사용자 PDF·프롬프트·출력을 로그나 GitHub Actions에 업로드하지 않는다.
7. 같은 로컬 윤문 기능을 모든 30/60/90k 원화 상품에 제공하는 것은 **최종 요구사항**이며, 3 SKU 실제 배포·판매 검증은 별개.
