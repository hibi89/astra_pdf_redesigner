# STEP 2 — 구현 결정 및 STEP 3 연계 (2026-10-18)

## 1. 사용자 확정 목표 (2026-10-18)
사용자가 원하는 최종 제품은 **기존 PDF를 업로드하면 문장, 숫자, 이미지, 표 등 원본 내용을 가능한 한 그대로 보존하면서 새로운 문서 디자인으로 재조판해 PDF로 저장하는 로컬 도구**다. 입력창에서 새로 글을 작성하는 것이 최종 핵심 기능은 아니다. **필요할 때 텍스트 블록을 클릭해 내용을 수정**할 수 있으면 좋다. 색상/폰트 조절은 디자인 부가 설정이다.

- **내용**과 **디자인**을 분리하여 저장한다. 디자인을 바꾸는 동작은 글과 숫자를 수정하지 않는다.
- 원문 보존은 입력 데이터/추출 결과에 대한 목표이다. 원본 PDF 자체의 페이지·위치·줄바꿈을 픽셀 단위로 유지한다는 뜻은 아니다.
- STEP 3에서는 텍스트 선택 가능한 단순·단일 열 PDF부터 시작하고, 추출 결과를 사용자에게 확인시킨다.
- 이미지를 완전하게 복원하지 못하거나 복잡한 표/다단/OCR 문서는 유실 가능성을 표시한다. 지원 범위가 아닌 경우 조용히 성공으로 처리하지 않는다.
- 사용자가 **아스트라 기존 7단계 로드맵을 유지**하기로 결정했다. STEP 2 문서 제작기를 먼저 만든 뒤 STEP 3 PDF 가져오기, STEP 4~7 디자인 확장을 따른다.
- 확정 근거: 이 채팅의 사용자 명시 확인(2026-10-18). 원본 설계 `docs/ASTRA_ORIGINAL_ROADMAP.txt`는 수정하지 않는다.

## 2. STEP 2 설계안 비교
| 방식 | 장점 | 단점 | 비용·성능·유지보수 |
| --- | --- | --- | --- |
| A. 기존 회고록 필드를 확장한 고정 양식 | 구현이 매우 간단, 현재 코드 대부분 유지 | 자유로운 섹션/이미지/순서 변경이 어렵고 STEP 3 추출 구조를 재작성해야 함 | 단기 저비용, 향후 재작업 발생 |
| **B. 순서 있는 소형 문서 블록 모델** | 제목·문단·이미지 편집 및 순서 변경, STEP 3 PDF 추출 블록의 수용 구조가 됨 | 초기 마이그레이션과 이미지 저장 검증이 필요 | 약간 높은 초기 비용, 장기 유지보수에 유리 |
| C. 자유 캔버스/드래그 편집기 | 배치 자유도 높음 | 복잡성·성능·모바일·인쇄 오류 위험이 크고 현재 범위 초과 | 높은 비용, 비추천 |

**선택: B.** 단, 블록 종류는 제목·문단·이미지로 제한하고 위/아래 버튼으로 순서 변경. 중첩 편집기·플러그인 구조·OCR·PDF 업로드를 STEP 2에 넣지 않는다.

## 3. STEP 2 구현 순서 (개발·검증용 작업 단위)
1. 데이터 모델 및 마이그레이션: `schemaVersion:1` STEP 1 저장 데이터를 **읽고** STEP 2 블록 모델로 변환. 기존 로컬 저장 키를 덮어쓰지 않고, 성공 전 원본 삭제 금지.
2. 기본 블록 편집: 추가/수정/삭제/위아래 이동, 제목·문단·이미지 설명, 직접 클릭 후 입력 수정.
3. 이미지: 사용자 로컬 PNG/JPEG/WebP만 처리, 파일 크기/형식 제한·오류 안내, Object URL 관리. 사용자가 선택한 이미지와 문서 메타는 IndexedDB 등 적절한 지속 저장소에 저장. 외부 전송 금지.
4. 문서 여러 개: 생성·선택·이름 변경·복제·삭제(확인 포함), 각각 독립 디자인 값 보존.
5. 프로젝트 내보내기·가져오기: 내용·디자인·이미지를 함께 복원하는 단일 휴대 가능한 내보내기 파일, 손상 데이터 거절과 기존 데이터 보호.
6. 인쇄 품질: STEP 1의 공통 렌더러/인쇄 CSS 유지, 이미지 비율·여러 페이지 분할·원문·한글 검증. 테스트 및 README/STATUS/HANDOFF 정리.

## 4. STEP 2 완료 기준
- STEP 1의 기존 회고록 작업본·인쇄 기능 회귀 없음.
- 사용자 지정 순서의 제목·문단·이미지 블록 저장/복원.
- 이미지 포함 문서의 PDF 인쇄에 누락/과도한 확대/잘림이 없음.
- 문서별 저장/불러오기, 내보내기 후 다시 가져오기에서 텍스트·디자인·이미지가 유지됨.
- 손상되거나 악성인 프로젝트 파일은 기존 저장 데이터에 영향을 주지 않으며, 실패 이유를 안내.
- GitHub Actions 빌드·테스트 + 가능한 실제 Chrome 확인. Windows/Edge 등 미검증은 명시.

## 5. 사용자 개입
이 단계는 PDF 샘플 없이 개발할 수 있다. 사용자가 **STEP 3**에서 실제 사용하려는 PDF를 제공하면, 원본 문장·이미지·표 비교 검증에 사용할 수 있다. 민감한 문서 대신 공개 자료 또는 개인정보를 제거한 샘플 권장.
