# ASTRA 서명형 오프라인 라이선스 검증 P96 — 구현·미완 경계

**최종완성률 공식 `UNASSESSED` / 목표 100%**. 이 문서는 상용 인증이 켜졌다는 증거가 아니다.

## 대안 비교 및 선택
- **A. localStorage의 BASIC/PRO/BUSINESS 문자열 플래그:** 개발은 쉽지만 수정만으로 무제한 잠금해제가 가능한 취약한 방식 → 채택하지 않음.
- **B. 발급자 비밀키 오프라인 서명 + 앱 공개키 검증:** 고객 문서·라이선스 조회 서버/구독이 필요 없고, 디바이스에서 서명을 확인하며 0원으로 테스트 가능 → **검증 모듈만 선구현**. 오프라인 복제 완벽 방지는 불가.

## 구현 범위
- `src/commercial/offlineLicense.ts`의 ECDSA P-256 공개키 가져오기 / 엄격한 payload 형태·만료·버전·발급일 확인 / 서명 검증 / BASIC8·PRO20·BUSINESS30 entitlement 매핑.
- Node/WebCrypto test-only 키쌍은 테스트 실행 시 임시 생성; 공개키·비밀키 어느 것도 Git 저장소에 판매용으로 고정하지 않음.
- **출시 불가:** 현재 실제 공급자 공개키 **핀 고정 미완**, 판매용 서명키 **미발급**, GUI 라이선스 활성화·기능 잠금/갱신·재발행·기기수 검증/약관 미구현. 키 없이 verify는 fail-closed지만 현 UI는 기존 임시 고급 시안 데모이며 실제 상용 SKU 기능을 라이선스에 따라 제한하지 않음.
- 발급자가 실수로 공개한 비밀키를 git 이력에서 제거/키교체하는 사고 대응, 버전·구매·환불·지원/재설치 정책, 오프라인 PC 시각조작·라이선스 복제 위험의 구매자 고지 필요.
- 실제 판매 전에 **소유자 별도 승인**으로 라이선스 발급 정책 및 실제 로컬 서명키 생성/백업 절차 확정. private key나 구매자 이름을 채팅/GitHub에 붙여 넣지 말 것.
