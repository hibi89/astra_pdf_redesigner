## PHASE 1 — MVP 기반 고정 (현재 제한 GO)
- PDF.js import, 원본 대조/수정·동의, STEP1/2 localStorage/IndexedDB, BASIC 8개 상이한 A4 디자인, Electron/NSIS PDF 저장, M09-A/B/C/D 경계 테스트 유지.
- 이미 구현·검증된 기능을 다시 만드는 데 시간을 쓰지 말 것. 기존 테스트가 통과한 코드는 변경 지점 중심으로 회귀한다.
- MVP는 내부 시연판이지 전체 사용성/고객 PC/상용 품질의 완료 판정이 아니다.

## PHASE 2 — 최초 설계 누락 기능 구현 (주 작업)
우선순위는 docs/ASTRA_ORIGINAL_ROADMAP.txt, docs/BLUEPRINT.md, REQUIREMENTS.md 및 gap matrix와 비교한다.

**P0 / STEP4 스타일 조합 엔진:** 기존 8개 프리셋을 보존하며 허용된 스타일 토큰(폰트/팔레트/여백/밀도/제목과 섹션/이미지 배치)과 레이아웃 프리셋을 구분. 동일 원문으로 2~3개 동시 스타일 비교, 즐겨찾기·저장·재사용, 적용 취소/복원, 실제 A4 PDF 동일원문 증명을 구현한다. 20/30개 템플릿 숫자만 늘리는 작업보다 앞선다.
- 설계 A: 독립 CSS/테마 하드코딩 — 구현 초반 빠르나 조합 증가·회귀 부담 큼.
- 설계 B: 제한된 디자인 토큰 스키마 + 사전 검증 프리셋 — 초기 구조 비용이 소폭 있으나 테스트·확장·STEP5 레퍼런스 연결에 유리. **B 우선 권고**. 기존 스키마 마이그레이션이나 중요 설계 변경이 필요하면 최적안을 제시하고 사용자 승인 후 구현.

**P1 / STEP5 로컬 레퍼런스:** 사용자 파일이나 외부 사이트를 무단 사용하지 않고 합성 이미지 fixture로 룰 기반 색상/여백/폰트 비율 추정 → STEP4 스키마에 매핑 → 수동 확인·수정·적용 취소를 설계하고 승인 범위에서 개발. 이미지나 PDF에서 원본 레이어/픽셀 동일 복제 보장 불가. 참조 PDF/URL 지원과 데이터 경계 변경은 별도 승인.

**P1 / STEP7 지원성·검수:** 허용된 텍스트 중심 PDF에 대해 누락 후보/수치·기호·이미지/문단 순서 경고, 실제 A4 넘침·잘림 확인, 장문/자원 경계, 취소/복구를 강화. 복잡한 표·다단 완벽 지원은 아직 주장하지 않는다.

**승인대기:** STEP6 인터넷 검색 연동, STEP7 OCR, 실제 한국어 오프라인 LLM 및 모델·런타임 다운로드, 외부 전송·유료 API, 라이선스/사용권 변경, 새 배포/PR merge. 승인 전에는 비교 설계·합성 fixture·비파괴 테스트만 가능. PRO20/BUSINESS30은 스타일 엔진/상용 조건이 갖춰진 뒤 확장하고, 세 SKU 동일 윤문이라는 제품 계약은 유지한다.
